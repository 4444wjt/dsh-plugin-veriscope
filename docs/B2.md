# B2：免装 VeriScope 的已有评分门禁

对应 **0.5.0 本地候选版**。B2 只读取已有逐条评分，按明确策略检查全部输入记录的均值，不生成评分、不调用模型，不等同原 VeriScope 正样本门禁。只需要 Node ≥22.19；不需要安装 VeriScope、Python、pandas 或 Ragas。

## 直接使用

在宿主启动前设置 `VERISCOPE_STATE_DIR` 为插件目录之外的可写持久目录。没有 settings UI，不读取 `.env`，不回退包目录；B2 不使用 `VERISCOPE_ROOT` 或 `VERISCOPE_PYTHON`。原 replay 的配置要求保留。

```powershell
$env:VERISCOPE_STATE_DIR = 'D:\your-data\veriscope-state'
node scripts/check.mjs --archive examples/builtin/archive.json --policy examples/builtin/policy.json --json
# 本地候选 tarball 安装后，也可使用 veriscope-check。
```

在已接入插件的 DSH／MCP 宿主中说：

> 使用 veriscope_gate_check，检查 D:\data\scores.json，按 D:\data\policy.json 的策略，输入格式为 ragas-records-v1。说明结果并保存回执。

工具参数为 `{archive_path, policy_path, format?}`，两个路径必须是绝对路径。`format` 默认 `gate-archive-v1`；Ragas 须显式使用 `ragas-records-v1`，不会猜测格式。CLI 的 `--archive`／`--policy` 可以使用相对路径，以 CLI 当前工作目录解析。

先体检可调用 `veriscope_doctor({engine:"builtin"})`；查询用 `veriscope_gate_status({run_id})`、`veriscope_gate_list({limit:10})`。status 只读检查，不重新判定；B2 不接受 status 的 `faith/ctx/baseline_run_id` 参数。没有前端设置页，B2 返回中文文本和结构化结果；原 status 卡片遇到 B2 时显示文本，不显示原正样本指标卡。

## 两份公开格式

规范：[GateArchiveV1 Schema](../schemas/gate-archive-v1.schema.json)、[GatePolicyV1 Schema](../schemas/gate-policy-v1.schema.json)。单份输入上限 10 MiB，策略上限 1 MiB；最多 100,000 条记录、100 项规则。超过限制拒绝，不截断后放行。

```json
{
  "schema_version": "GateArchiveV1",
  "source": { "producer": "your-evaluator", "version": null },
  "rows": [
    { "id": "case-1", "scores": { "faithfulness": 0.9, "latency_ms": 120 } },
    { "id": "case-2", "scores": { "faithfulness": 0.9, "latency_ms": 160 } }
  ]
}
```

`source` 是提供方声明，不是独立核验；版本未知用 `null`。`id` 必须唯一且非空。`scores` 中所需指标缺失、为 `null` 或类型非法时保留对应记录，不删除或补造评分。

```json
{
  "schema_version": "GatePolicyV1",
  "aggregation": "mean",
  "population": "all_provided_rows",
  "rules": [
    { "metric": "faithfulness", "unit": "ratio", "operator": "gte", "threshold": 0.8, "range": { "min": 0, "max": 1 } },
    { "metric": "latency_ms", "unit": "ms", "operator": "lte", "threshold": 150 }
  ]
}
```

每项规则必须显式给出原指标名、单位、方向和有限阈值。`gte` 为大于等于，`lte` 为小于等于；不继承 replay 的默认阈值。可选 `range` 至少声明有限 `min/max` 之一，阈值须在范围内。不接受重复指标、未知字段、筛选、权重、分位数、基线或执行命令。单位只展示并绑定，不猜测或自动换算。

首版对输入全部记录作等权均值，按原始行序使用 JavaScript 浮点数求算，不提前舍入、不增加容差。CLI 退出码为 PASS=0、FAIL=1、REVIEW／执行故障=2；已确认 FAIL 同时发生写入故障时仍保留 FAIL／1，并单列错误。

## 缺失值与三态

- 每个指标报告总数、有效数、缺失数、非法数及最多 20 条问题记录编号；超出时标记截断。问题清单截断不改变统计分母。
- 该指标有缺失／非法值时，完整均值为 `null`、指标为 REVIEW，不使用有效子集的均值放行。
- 所有所需指标完整且达标才 PASS；任意完整指标确认未达标即 FAIL；否则 REVIEW。空数据为 REVIEW。
- JSON 解析、格式或策略校验失败不执行判定，不生成回执。实际执行后，数据不完整的 REVIEW 可以生成 ReceiptV2，记录为何无法判定。
- 仅检查输入内完整性，无法发现导出前已删除的记录。PASS 不证明评分真实、回答事实正确、原评测总体完整或可安全发布。

## Ragas 导出接入

从**已经完成**的评测结果导出，不重新调用 `evaluate`：

```python
result.to_pandas().to_json(
    "scores.json", orient="records", force_ascii=False
)
```

本适配以 [Ragas v0.4.3 EvaluationResult.to_pandas](https://docs.ragas.io/en/v0.4.3/references/evaluation_schema/) 与 [pandas records JSON 布局](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.to_json.html)为参考；消费端不安装这些库。只接受逐行对象数组，不支持 CSV、终端汇总字典、其他 `orient` 或 JSONL。pandas 会将 NaN／None 导出为 `null`，本工具保留缺失。

```powershell
node scripts/check.mjs --archive scores.json --policy policy.json --format ragas-records-v1 --json
```

策略指标名必须与原列名完全一致。不会把 `faithfulness` 改成 `pos_faithfulness`，也不会根据 `case_type` 自动选择正样本。行编号使用原数组顺序 `row-1`、`row-2`；来源版本未知保持 `null`。不根据其他数值列猜测评分，不从问题或回答中补数据。

全体均值与正样本均值可以产生相反结论：阈值 0.8，正样本 0.7、负样本 1.0 时全体均值 0.85，但正样本不达标；正样本 0.9、负样本 0.1 时全体均值 0.5，但正样本达标。这是两种明确不同的策略，不能互换字段。

仓库样例均为按文档构造的协议样例，不是真实评测或真实用户历史。支持的是这个已声明的布局，不是全部 Ragas 版本与导出方式。

## 回执、状态与导出

`ReceiptV2` 明确标识 `builtin-threshold-v1 / 1.0.0`，绑定原输入字节、策略字节、规范化数据摘要、规则摘要、适配器与判定代码、插件版本，以及 Node 版本、平台、架构和执行文件位置。没有 Python 命令、子进程退出码、pandas 版本或伪造会话字段。DSH 报告可记录宿主真实会话；MCP／CLI 的执行会话为 `null`。

运行目录中保存 `input.json`、`policy.json`、`normalized.json`、`report.json` 与满足条件时原子发布的 `receipt.json`。不覆盖已有记录。`report.json` 是判定与执行核心；返回的 `recording` 单列保存结果，不能拿它代替当前 status。保存失败时返回诊断并尽可能另存 `recording-error.json`，没有有效回执不能作为可复用 PASS；已确认 FAIL 不被保存错误覆盖。

status 按回执版本分派。ReceiptV2 只检查字节、绑定项与产物，不启动 Python、不重新判定；同路径保持 mtime 的字节变化仍会失效。ReceiptV1 继续使用原契约与原环境检查。升级共有代码后旧回执的当前有效性可能进入 REVIEW，历史裁决不改写；升级前备份完整状态根及原输入。

DSH 的既有 export 支持 B2 `json`／`md`，JSON 单条保留原回执字节，Markdown 列明判定器、单位和实际策略。B2 `share` 明确不支持，混合批次也不导出部分分享摘要。JSON 回执不是完整备份；本地报告和原始输入可能敏感，分享前自行审阅，不自动上传。

B2 首版不进入 batch／bind／complete；原 batch 只处理原 VeriScope 格式。B2 的 PASS 不能用于登记受管任务完成。清理 CLI 能列出两种回执及容量，仍只预演、无限期保留，没有删除入口。
